## Keep the source. Inspect the structure.

Zirium's parser retains the original bytes, including comments, whitespace and
malformed input. A separate semantic document resolves SSA values, types and
symbols for queries, comparisons and transactional edits. Choose the
representation that fits the work.

## Installation

Install the published Python package:

```sh
python -m pip install zirium==0.5.0
```

Wheels cover conventional CPython 3.11–3.14 on Linux x86_64 and macOS arm64.
Other platforms and free-threaded CPython are unsupported. The Python wheel
does not include the CLI.

With Rust 1.88 or newer, install the published CLI:

```sh
cargo install zirium --version '=0.5.0' --locked
```

For a Rust application, add the library with `cargo add zirium@=0.5.0` and consult the
[Rust API reference](https://docs.rs/zirium/0.5.0/zirium/). The
[getting-started guide](./guides/getting-started/) covers library usage and
building from a checkout.

### CLI binaries

[GitHub Releases](https://github.com/zayenz/zirium/releases/tag/v0.5.0) provides standalone
CLI archives for Linux x86_64 (static musl) and macOS arm64. These do not require
Rust, Python or LLVM. Follow the
[download and checksum instructions](https://github.com/zayenz/zirium/blob/v0.5.0/README.md#cli-binaries)
for your platform.

## Try a query

This example reads generic MLIR from stdin and needs no dialect registry:

```sh
printf '%s\n' '%value = "example.make"() : () -> i32' | zirium 'names | tally | json'
```

For a file using registered custom syntax, choose a preset and use strict
lowering to reject incomplete semantic information:

```sh
zirium --preset stablehlo --strict 'names | tally | json' model.mlir
```

The [query language reference](./guides/query-language/) lists predicates and
pipeline stages. The [preset reference](./guides/registry-presets/) records
which custom forms each registry supports. For calculated reports, the shared
[Zirql value guide](https://zayenz.se/zirql/guides/values/) explains expressions,
comprehensions and collection order. MLIR navigation and edits are defined by
Zirium's query reference.

## Know the boundaries

Zirium is experimental and its API may change without a migration path. Its
textual syntax target is MLIR 22.1, with selected custom dialect forms.
Presets support structural inspection; they do not provide complete dialect
verification, type inference or execution. Bytecode and ODS/TableGen loading
are unsupported.

Original output reproduces the input bytes. Formatting, canonical output and
source-preserving edits each have a different contract. Read the
[capability reference](./guides/capabilities/) and
[structural editing guide](./guides/structural-editing/) before choosing an
output path.
